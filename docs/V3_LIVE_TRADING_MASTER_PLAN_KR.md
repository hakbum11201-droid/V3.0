# coinB V3 Live Trading Master Plan (실거래 전환 마스터 플랜)

## 1. 비전 및 최종 목표
- **비전:** 단순 프로토타입을 넘어, 개인이 실제로 장기간 운영하며 수익을 창출할 수 있는 전문 급 자동매매 시스템 구축.
- **최종 목표:** 1인 개인이 로컬 환경에서 직접 운영하는 업비트 KRW 마켓 최적화 자동매매 솔루션.
- **핵심 가치:** 
  1. **안전 제일:** DDM(Drawdown Defense Manager)과 MDD 관리를 통한 원금 방어 최우선.
  2. **철저한 검증:** 실거래 전 최소 1주일 이상의 Paper Trading 검증 필수.
  3. **데이터 중심:** Microstructure 분석과 Orderflow 기반의 정밀한 진입/청산.
  4. **단계적 전환:** tiny_live(소액 실거래)를 통한 시장 충격 및 체결 오차 검증 후 정규 실거래 전환.

## 2. 현재 상태 (V3.1 Foundation 완료)
- [x] Upbit 공개 WebSocket 데이터 수집 및 Microstructure 계산
- [x] Orderflow 기반 Paper Trading 엔진 및 반복 루프 구현
- [x] Learning Log, Loss Analysis, Paper Review, Config Candidates 등 분석 체계 구축
- [x] Streamlit 기반 로컬 관제 UI (한국어)
- [x] DDM Foundation 및 UI 표시
- [x] DDM Gate를 통한 Paper 신규 진입 자동 차단 연동

## 3. 단계별 실거래 전환 로드맵

### Phase 1: 성과 추적 및 리포트 정밀화 (현재 진행 중)
- **목표:** Paper Trading의 PnL, Drawdown, 승률 등을 정확히 계산하고 UI에 시각화.
- **주요 작업:**
  - `paper_engine` 내 실시간 Equity Curve 계산 로직 추가.
  - MDD 및 연속 손실 횟수 추적.
  - 리포트 내 Config 후보 간 성과 비교 기능.

### Phase 2: 계좌 관리 및 조회 전용 연동
- **목표:** 실제 업비트 계좌의 자산 상태를 안전하게 모니터링.
- **주요 작업:**
  - **조회 전용(Read-Only)** API Key 사용 가이드 및 구현.
  - `.env` 파일을 통한 API Key 관리 및 보안 강화.
  - UI에 실제 계좌 잔고 및 평가 금액 표시.

### Phase 3: 장기 검증 및 리스크 튜닝
- **목표:** 다양한 시장 상황(상승, 하락, 횡보)에서의 시스템 안정성 검증.
- **주요 작업:**
  - 최소 7일 이상의 무중단 Paper Trading 운영.
  - DDM 차단 로직의 민감도 조정.
  - 슬리피지 및 체결 비용 모델의 실제 데이터 기반 보정.

### Phase 4: tiny_live (소액 실거래) 진입 준비
- **목표:** 시스템의 주문 기능 활성화 및 실환경 체결 테스트.
- **주요 작업:**
  - `live.enabled=true` 전환을 위한 코드 게이트 해제 (별도 승인 절차).
  - 주문 권한 포함 API Key 사용 개시.
  - 최소 주문 단위(예: 5,000원 ~ 10,000원) 기반의 tiny_live 모드 구현.
  - 실제 체결 가격과 가상 체결 가격의 오차 분석.

### Phase 5: 정규 실거래 전환 및 운영 최적화
- **목표:** 안정적인 자산 운용 단계 진입.
- **주요 작업:**
  - 가용 자산의 일정 비율(예: 10~20%)로 시작하여 단계적 증액.
  - 시장 상황 변화에 따른 Config 후보 자동 알림 및 수동 적용 체계.
  - 주기적인 성과 분석 리포트 자동 생성 및 백업.

## 4. 핵심 안전 및 운영 원칙
1. **실거래 금지 해제 조건:** 장기 Paper Trading에서 MDD가 허용 범위 내에 있고, 예상 수익률이 플러스인 경우에만 tiny_live로 전환한다.
2. **DDM 우선주의:** DDM이 `BLOCK_NEW_ENTRY` 상태일 경우, 어떠한 상황에서도 신규 매수는 금지하며 기존 포지션의 안전한 정리(청산)에만 집중한다.
3. **API Key 보안:** API Key와 Secret은 절대 GitHub에 커밋하지 않으며, 주문 권한이 있는 Key는 필요한 시점에만 활성화한다.
4. **수동 설정 원칙:** Config는 시스템이 제안한 후보를 사람이 직접 검토한 후 수동으로 반영하며, 자동 설정 변경은 원칙적으로 금지한다.
5. **UI 중심 관제:** 모든 시스템 상태는 한국어 기반의 Streamlit UI를 통해 실시간으로 모니터링하며, 이상 징후 발생 시 즉시 중단한다.

## 5. 제외 대상 (Out of Scope)
- 다계좌 연동 및 다중 사용자 서비스 제공.
- 외부 클라우드 서버 기반의 불특정 다수 대상 서비스.
- 고빈도 매매(HFT)를 통한 무리한 수익 추구.
- 비공개/불법 데이터를 활용한 매매.
