# coinB V3 Live Trading Master Plan KR

## 0. 문서 목적

이 문서는 coinB V3 프로젝트의 최상위 실거래 전환 기준서다.

본 프로젝트는 단순 프로토타입이나 장난감 자동매매 프로그램이 아니다.  
최종 목표는 **1인 개인이 로컬 PC에서 직접 운영할 수 있는 업비트 KRW 마켓 기준 실거래 전환 가능 자동매매 시스템**이다.

단, 현재 단계에서는 실거래를 절대 활성화하지 않는다.  
현재의 목적은 실거래 전환 전에 필요한 데이터 수집, 주문흐름 판단, 리스크 방어, 성과 검증, 보안 구조를 완성하는 것이다.

---

## 1. 최종 목표

### 1.1 최종 목표 정의

coinB V3의 최종 목표는 다음과 같다.

- 업비트 KRW 마켓 기준 개인용 자동매매 시스템
- 후행성 차트 지표가 아니라 WebSocket 체결/호가 기반 주문흐름 분석 중심
- 수수료, 스프레드, 슬리피지, 미체결 위험을 차감한 net_pnl 기준 성과 평가
- DDM(Drawdown Defense Manager)을 통한 손실 방어
- Keyless Paper Mode → Read-only 계좌 조회 → tiny_live → 제한적 실거래 순서로 단계 전환
- 공개 GitHub 저장소에서도 안전하게 관리 가능한 보안 구조 유지

### 1.2 실사용 성과 목표

성과 목표는 총수익률이 아니라 **연환산 net_pnl** 기준이다.

- 실사용 최소 목표: 연환산 net_pnl 5% 이상
- 우수 성과 목표: 연환산 net_pnl 10% 이상
- 공격적 성과 목표: 연환산 net_pnl 20% 이상

net_pnl은 다음 비용을 모두 차감한 순수익이다.

- 매수 수수료
- 매도 수수료
- 스프레드 비용
- 예상 슬리피지
- 미체결/부분체결 위험 비용
- 손절 비용

연 5% 미만이면 자동매매를 실사용할 경제적 의미가 약하다.  
연 10% 이상은 우수한 성과로 본다.  
연 20% 이상은 매우 공격적인 성과이므로 MDD, DDM, 연속 손실, 일일 손실 제한을 더 엄격하게 관리해야 한다.

### 1.3 우선순위

수익보다 생존이 먼저다.

우선순위는 다음과 같다.

1. 원금 방어
2. MDD 제한
3. DDM 정상 작동
4. 수수료 후 기대값 양수
5. 충분한 거래 표본
6. 총수익률

거래 횟수는 목표가 아니다.  
거래 횟수는 좋은 조건이 반복해서 발생했을 때 따라오는 결과다.

## 2. 전략 철학

## 2.1 후행성 차트 지표 중심 매매 지양

본 시스템은 RSI, MACD, 이동평균선 같은 후행성 차트 지표 중심 자동매매를 지양한다.  
주요 판단 데이터는 업비트 WebSocket 기반의 실시간 체결/호가 흐름이다.

주력 데이터는 다음과 같다.

- 실시간 체결 데이터
- 실시간 호가 데이터
- 1~5단계 호가 깊이
- 매수/매도 체결대금
- 스프레드
- 가격 변화율
- 호가벽 변화
- OFI(Order Flow Imbalance)
- Sweep
- Absorption
- Continuation

온체인 데이터, 뉴스, 외부 지표는 향후 보조 경고 지표로만 검토한다.  
현재 핵심은 업비트 내부 체결/호가 흐름이다.

---

## 3. 최종 전략 구조

최종 구조는 단순 필터 누적 방식이 아니다.  
필터를 과도하게 AND 조건으로 쌓으면 거래가 사라진다.

따라서 전략 판단은 다음 3단계로 분리한다.

1. Hard Block
2. Soft Score
3. Net Edge Gate

---

## 3.1 Hard Block

Hard Block은 절대 거래하면 안 되는 조건이다.  
여기 걸리면 무조건 신규 진입을 차단한다.

Hard Block은 많으면 안 된다.  
치명적 위험만 차단한다.

Hard Block 조건은 다음과 같다.

- 업비트 유의종목, 주의종목, 거래지원 종료 예정 종목
- 데이터 지연 또는 WebSocket 오류
- DDM DATA_ERROR
- DDM BLOCK_NEW_ENTRY
- BTC 급락 또는 시장 전체 급락
- 스프레드가 목표 익절폭보다 큰 상태
- 호가 깊이가 주문금액 대비 부족한 상태
- 출구 유동성이 부족한 상태
- 일일 손실 한도 초과
- MDD 한도 초과
- 연속 손실 한도 초과
- API 오류 또는 체결 오류 반복
- 실거래 승인 조건 미충족

Hard Block은 수익 기회를 줄이더라도 반드시 유지한다.  
손실이 크게 날 수 있는 구간은 애초에 거래하지 않는다.

---

## 3.2 Soft Score

Soft Score는 거래 품질을 점수화하는 영역이다.

여기서 균형을 잡는다.  
모든 조건을 반드시 통과시키는 방식이 아니라, 여러 주문흐름 요소를 점수화한다.

예시 구조는 다음과 같다.

```text
Orderflow Score =
체결 강도
+ OFI
+ 호가 흡수
+ Sweep 이후 가격 유지
+ Continuation
+ 호가 깊이
- 스프레드 부담
- 급등락 위험
- 유동성 부족 위험
